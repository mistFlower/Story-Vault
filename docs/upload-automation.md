# 플랫폼 업로드 자동화 — 현황과 선택지

노벨피아·조아라에 로그인해서 회차를 자동 업로드하는 기능에 대한 정리다.
**아직 구현하지 않았다.** 먼저 확인해야 할 것들이 있어서다.

## 1. 공개 API가 없다

두 플랫폼 모두 **작가용 공개 API를 제공하지 않는다.** 개발자 문서, API 키 발급,
OAuth 앱 등록 같은 것이 없다. 따라서 "API 추출"은 실제로는
**웹사이트가 내부적으로 쓰는 비공개 엔드포인트를 역분석하는 것**을 의미한다.

## 2. 내가 직접 추출할 수 없는 이유

비공개 API를 알아내려면 **로그인된 상태의 네트워크 트래픽**을 봐야 한다.

- 나는 두 플랫폼의 계정이 없고, 로그인 세션을 만들 수 없다.
- 로그인 없이 접근 가능한 페이지에는 업로드 엔드포인트가 노출되지 않는다.
- 따라서 트래픽 캡처는 **계정 소유자가 직접** 해야 한다.

캡처 방법은 아래 4항에 적어뒀다.

## 3. 먼저 알아야 할 위험

구현 여부를 정하기 전에 알고 있어야 하는 것들이다.

### 이용약관

두 플랫폼 모두 이용약관에 **자동화된 접근·비정상적 접근을 금지하는 조항**이
있을 가능성이 높다. 본인 계정에 본인 원고를 올리는 것이라도, 약관상
자동화 자체가 문제가 될 수 있다. **약관을 직접 확인하고 판단해야 한다.**

### 계정 정지 위험

이게 실질적으로 가장 큰 위험이다. 연재 중인 작품이 있는 계정이 정지되면
손실이 크다. 자동화 트래픽은 다음으로 탐지될 수 있다.

- 비정상적인 요청 간격·패턴
- 브라우저가 아닌 User-Agent
- 정상 플로우를 건너뛴 직접 엔드포인트 호출

### 로그인 자체의 난관

- 캡차(reCAPTCHA 등)가 있으면 자동 로그인이 막힌다.
- 2단계 인증이 걸려 있으면 마찬가지다.
- 소셜 로그인(네이버·카카오)을 쓰면 흐름이 더 복잡하다.

**캡차를 우회하는 방향으로는 구현하지 않는다.** 봇 탐지를 뚫는 것은
"내 계정에 내 글 올리기"의 범위를 넘어선다.

## 4. 트래픽 캡처 방법 (직접 하셔야 함)

역분석에 필요한 자료를 뽑는 절차다.

1. 크롬에서 해당 플랫폼에 **로그인**한다.
2. `F12` → **Network** 탭 → **Preserve log** 체크
3. 회차 하나를 **실제로 업로드**한다 (비공개/임시저장으로 해도 된다)
4. Network 탭에서 우클릭 → **Save all as HAR with content**
5. HAR 파일을 열어 **쿠키·토큰·비밀번호를 반드시 지운다**

> HAR에는 세션 쿠키가 그대로 들어간다. 지우지 않고 공유하면
> 그 파일을 가진 사람이 계정에 접근할 수 있다. 공유 전 반드시 확인한다.

이렇게 정리된 HAR을 주시면 요청 형식·필수 필드·인증 방식을 분석해
클라이언트를 작성할 수 있다.

## 5. 대안 세 가지

| 방식 | 안정성 | 위험 | 설명 |
|---|---|---|---|
| **A. 반자동 (권장)** | 높음 | 없음 | 앱이 회차를 플랫폼 형식으로 변환하고 클립보드에 복사 + 업로드 페이지를 열어준다. 붙여넣기와 게시 버튼만 직접 누른다. |
| **B. 브라우저 자동화** | 중간 | 중간 | Playwright로 실제 브라우저를 띄워 사람처럼 조작한다. 로그인은 사용자가 직접 하고 세션을 재사용한다. UI가 바뀌면 깨진다. |
| **C. 비공개 API 직접 호출** | 낮음 | 높음 | 가장 빠르지만 엔드포인트가 바뀌면 즉시 깨지고, 탐지 위험이 가장 크다. |

A안은 실질적으로 손이 두 번 더 가는 대신 **계정 위험이 0**이다.
분량 검증(노벨피아 글자 수 / 조아라 KB)은 이미 앱이 하고 있으므로,
실제로 줄어드는 수고의 대부분은 A안으로도 얻어진다.

## 6. 어댑터 인터페이스

어느 방식을 고르든 앱 쪽 구조는 같다. `src/lib/publish.ts` 에
플랫폼 무관 인터페이스를 정의해두었고, 방식이 정해지면 어댑터만 갈아끼우면 된다.

## 결론

**어느 방식으로 갈지 정해주셔야 진행할 수 있다.**
현재 저장소에는 A안의 토대(형식 변환 + 분량 검증)까지만 들어 있다.
